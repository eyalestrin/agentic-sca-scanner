# SKILL: Agentic SCA & Dependency Vulnerability Scanner

## 1. Overview & Goal
This skill enables an agent or execution environment to perform Software Composition Analysis (SCA) across a target project folder (including all sub-directories). It parses both direct and transitive package manifests, checks every identified package against public advisory databases (OSV/NVD/GHSA), determines upgrade paths, and produces clear, actionable reports.

---

## 2. Supported Ecosystems & Manifest Files

| Ecosystem | Direct Manifest | Transitive Lock File |
| :--- | :--- | :--- |
| **Node.js (npm/yarn/pnpm)** | `package.json` | `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock` |
| **Python** | `requirements.txt`, `pyproject.toml` | `Pipfile.lock`, `poetry.lock` |
| **Go** | `go.mod` | `go.sum` |
| **Java** | `pom.xml`, `build.gradle` | `gradle.lockfile` |
| **Ruby** | `Gemfile` | `Gemfile.lock` |
| **.NET / C#** | `.csproj`, `packages.config` | `packages.lock.json` |

---

## 3. Execution Pipeline & Rules

### Step 1: Directory Discovery & Dependency Resolution
1. Recursively search the provided root directory for manifest and lock files.
2. Extract direct dependencies and exact resolved versions for transitive dependencies.
3. Map parent-child dependency relationships to preserve context for nested/transitive vulnerabilities.

### Step 2: Vulnerability Auditing
1. Query official open-source advisory APIs (e.g., https://api.osv.dev/v1/query) for each package-version combination.
2. Collect for each hit:
   - Advisory IDs (CVE, GHSA)
   - Severity & CVSS Score
   - Summary of impact
   - List of fixed versions in the advisory ecosystem

### Step 3: Upgrade & Remediation Analysis
1. Compare current package versions against available fixed versions in official package registries.
2. Recommend the lowest patched version that resolves all advisories without introducing unnecessary major-version breaking changes when possible.
3. **No-Patch Handling:** If a package has known vulnerabilities but no patched version exists in the official repository:
   - Explicitly tag the status as `NO_PATCH_AVAILABLE`.
   - Include a mandatory note in the generated report alerting developers to the unpatched risk and offering alternative mitigation strategies (e.g., library replacement, compensating security controls).

---

## 4. Output Format Requirements

All reports generated by this skill must follow a clean Markdown layout:

1. **Executive Summary Table:** Highlighting Total Packages, Direct vs. Transitive breakdown, Total Vulnerabilities, and Unpatched Package count.
2. **Vulnerability Details Section:** Grouped by package location, containing:
   - Package Name & Version
   - Manifest File Location
   - Direct or Transitive Flag (with parent path if transitive)
   - Vulnerability IDs & References
   - Severity Level
   - Remediation / Upgrade Recommendation
   - Specific Notes (mandatory if `NO_PATCH_AVAILABLE`)

---

## 5. Usage Command
```bash
python sca_scanner.py --path /path/to/target/project --output sca_report.md
```
